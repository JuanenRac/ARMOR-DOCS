# Capability matrix

What each capability is *today*, in three honest levels:

* **Simulated**: works against the simulator or a test double only.
* **Local**: works and is tested on a computer (unit, integration or host tests) with no real device.
* **Verified**: proven on the real hardware, with a measurement record.

A few rows say something between those: *None* (nothing runs yet, only text or a build), *Absent* (nothing exists), *Local, not activated* (built and tested, off by default) and *Verified on one camera / on the bench / on a phone* (the evidence is that narrow, and the row says which).

**Only the rows marked *Verified* have met real hardware: the CM5 test bench (in daily use, with the server, Studio, the network node, the voice and observation services, the broker and the maintenance helpers), real IP cameras, ARMOR-RADAR nodes (Waveshare ESP32-S3-ETH) that have been built, flashed and run, and a real phone running the Android app against the real server. No inverter, battery, electrical meter, alarm zone, siren, Zigbee coordinator or touch panel has been connected.** This page is updated with every change; a row moves to
*Verified* only with evidence (see [bench acceptance](https://github.com/JuanenRac/ARMOR-HARDWARE/blob/main/docs/BENCH_ACCEPTANCE.md)).
